Jellyfin permissions

Leave a permission as Unchanged to retain the user's existing Jellyfin setting. Explicit Allow/Deny is enforced while the user is enrolled. The original value is restored when unenrolled or set back to Unchanged. Subscription expiration still uses access schedules.

Seerr request access

When a managed subscription expires, requesting is denied in Seerr. When unenrolled or set back to Unchanged, the original request permissions are restored. Seerr administrators/managers are excluded.

Changing a price affects future renewals, not months already paid for. Hiding a plan does not cancel existing subscribers.

Seerr integration

Connect to Seerr from the Jellyfin server, using the Seerr base URL and API key. The key stays in the server's subscription data file and is never sent back to the web page. Seerr must already be configured to use this Jellyfin server.

Test checks the URL and key currently typed in the fields, even before saving. If there isn't already a working saved connection, a successful test automatically saves the entered settings; a failed test NEVER saves. When a working saved connection exists, Test won't overwrite it; use Save to update it.

If auto-import is off, users must already exist in Seerr. Sync uses their Jellyfin user IDs, not names. Only request-related permissions are managed; existing admin and manager permissions are never overridden.

Access synchronization

Runs automatically at startup and every five minutes. You can also reconcile now. Subscription restrictions use the Jellyfin access schedule; unrelated user settings are retained.

Data & migration

Data is saved under Jellyfin's data directory in subscription-manager/subscriptions.json with a previous-state backup. Existing subscription dates from the old JavaScript are not imported automatically. Use individual user settings to enter their current paid-through dates.
